# AdMind 产品决策包 v1

**状态：** 待产品负责人确认；确认后作为 Phase 1 的冻结基线  
**更新时间：** 2026-08-12  
**适用阶段：** 原型设计与可执行纵向闭环  
**一句话定义：** 在广告必须履约的商业约束下，为长视频选择更安全的投放时机、形式和已审批素材版本。

---

## 1. 本轮需要确认的决定

这份文件不是新的头脑风暴，而是把此前调研转成可开发的选择。除非后续证据推翻，Phase 1 按下列决定执行。

| 决策项 | v1 决定 | 暂不做的事情 |
|---|---|---|
| 产品类型 | 长视频广告决策模拟与分析平台 | 广告拦截器、浏览器插件、真实广告交易平台 |
| 产品名称 | AdMind Decision Studio | 为追逐热点而改名为通用 Agent |
| 核心决策 | 先规划整场广告负荷，再为当前机会选择`广告活动 + 已审批素材版本 + 机会/观众状态 + 时间 + 形式` | 只做“给谁推荐哪条广告”或只做孤立单点评分 |
| 首要用户 | 平台商业化/广告运营人员；演示中同时呈现观众视角 | 面向普通用户收费的独立 App |
| 首个平台范围 | 桌面端长视频的模拟环境 | 同时覆盖短视频、电商、直播、公众号、电视端 |
| AI 的职责 | 分析场景和生成基于理由码的可读解释 | 绕过规则直接决定或渲染广告 |
| 商业数据 | 透明、可复现的模拟合同、预算和曝光目标 | 声称掌握腾讯内部出价、用户或收入数据 |
| 内容与广告素材 | 原创、获得许可或明确可公开使用 | 将真实腾讯视频画面和广告放进公开仓库 |
| 第一阶段验证 | 相同商业约束下，AdMind 能否找到更低打断成本的可行方案 | 用小样本宣称真实收入或留存提升 |
| 工程形态 | 模块化单体 + 可选后台任务 | 微服务、Kafka、Kubernetes 等无必要基础设施 |

## 2. 产品判断

### 2.1 要解决的问题

广告平台面对的不是“广告或无广告”的单选题。现实中可能存在必须完成的合同、临近截止的曝光目标、高价值竞价或补量库存。AdMind 解决的是：

> 当候选广告已经由商业机制进入可投池后，系统能否在政策、合同和频控不被破坏的前提下，找到打断更小且更可解释的投放方案？

这个方案由五部分构成：

```text
Campaign + Creative Variant + Opportunity/Viewer State + Scheduled Time + Format
```

因此，一条广泛投放、与当前内容关系很弱但必须履约的游戏广告仍可能出现；AdMind 的价值是决定它是否应该延后、缩短、静音、改用低遮挡形式，或者在无可行机会时明确暴露履约风险。

### 2.2 为什么这是一个有分量的作品集项目

项目的复杂度来自真实决策，而不是页面数量：

- 商业合同、竞价价值和曝光进度；
- 内容语义、情绪强度、自然转场和敏感场景；
- 形式、时机、素材版本和跨形式频控；
- 硬规则、多目标排序、回退与人工修正；
- 决策审计、事件账本和可复现实验；
- 隐私、证据来源和不确定性表达。

一个招聘者应能在五分钟内看懂问题、比较两种策略、检查决策理由，并确认结果来自可重放的规则和数据。

## 3. 产品目标与非目标

### 3.1 Phase 1 必须实现

1. 在预置场景中切换 `Baseline` 与 `AdMind`。
2. 展示同一批合同、广告和视频机会下两种策略的不同结果。
3. 至少支持全屏视频、低遮挡卡片和延后投放三类结果。
4. 每次决定均展示候选方案、硬规则淘汰原因、评分分解和回退路径。
5. 通过事件账本记录决定、展示、可视、完成、关闭、恢复和离开。
6. 不使用 AI 密钥也能完整运行预置 Demo。
7. 关键场景具备自动化测试和确定性重放。
8. 用轻量会话规划器展示整场广告负荷、计划广告段、集中/分散偏好和未分配履约风险。

### 3.2 Phase 1 明确不做

- 接入腾讯视频、抓取真实用户或绕过平台控制；
- 真实广告竞价、结算、归因或身份图谱；
- 上传任意视频后的实时多模态分析；
- 自动生成未经广告主审批的宣传内容；
- 根据面部、摄像头、麦克风或敏感属性判断观众情绪；
- 把模拟的退出风险、收入或注意力称为线上效果；
- 同时开发完善的广告主后台和平台管理员后台。
- 生产级跨全站库存优化；Phase 1 的整场计划只对一个模拟观看会话使用确定性启发式规划。

## 4. 用户与核心任务

### 4.1 第一用户：平台商业化/广告运营人员

核心任务：

> 当一条广告需要完成交付时，找到仍满足合同和政策的低打断方案，并知道为什么系统延后、改形式或报警。

需要看到：

- 合同类型、目标、进度和剩余时间；
- 当前机会为什么可投或不可投；
- 哪些方案因硬规则被淘汰；
- 系统在商业价值和体验成本之间做了什么权衡；
- 如果无法履约，应采取什么运营动作。

### 4.2 第二用户：平台产品/策略负责人

核心任务：

> 用同一组可复现数据比较传统基线与 AdMind，判断策略变化是否值得继续实验。

需要看到：

- 合同可行性是否保持；
- 硬规则违规是否为零；
- 打断成本、遮挡、重复和恢复体验是否改善；
- 指标是模拟、观察、用户报告还是外部来源。

### 4.3 被影响用户：观众

观众不是 Phase 1 后台的直接购买者，但其体验必须在播放器中可见：广告标识清楚、关闭控件可用、暂停时不遮挡重要信息、内容能在清晰边界恢复，并可提交“时机不对/重复/不相关/遮挡”等反馈。

## 5. 产品体验：从进入到看懂结果

```text
场景库
  ↓ 选择一个预置案例
策略对比播放器
  ↓ 在 Baseline / AdMind 间切换或并排重放
决策检查器
  ↓ 查看候选、淘汰理由、分数、证据和回退
会话结果
  ↓ 比较履约、打断、频次、反馈和规则违规
```

### 5.1 页面 A：场景库

每张场景卡必须展示：

- 场景名称与一句话冲突；
- 商业压力，例如“保证量合同还差 18%”；
- 体验风险，例如“情绪高潮/正在查看关键信息/敏感任务”；
- 将要验证的产品能力；
- `运行对比` 按钮。

### 5.2 页面 B：策略对比播放器

默认使用单播放器切换策略，避免两个视频同时播放导致认知和性能问题。页面包括：

- 视频与场景时间轴；
- `Baseline` / `AdMind` 切换；
- 当前合同与广告候选摘要；
- 整场广告计划条：计划广告段、预计广告负荷、剩余广告债务和计划变更；
- `集中一次看完 / 分散到安全转场`偏好（仅在场景允许时启用）；
- 即将发生的机会提示；
- 广告实际形式与恢复行为；
- 回消息、看弹幕、拖动进度、返回页面等交互发生时，广告是否撤下、延后或保持不遮挡；
- `为什么这样决定？` 入口。

“并排摘要”只比较关键帧、时间点和结果，不要求两个完整视频同步播放。

### 5.3 页面 C：决策检查器

检查器按以下顺序解释，不能只给一句大模型生成的话：

1. 当前机会和上下文；
2. 硬规则检查；
3. 合格的完整投放方案；
4. 各评分分量；
5. 入选方案与备选方案；
6. 人类可读说明；
7. 引擎、规则、场景分析版本与数据来源。

### 5.4 页面 D：会话结果

同一场景同时列出 Baseline 与 AdMind：

- 合同需要/成功交付；
- 可视和完成状态；
- 广告出现时间与形式；
- 规范化打断成本；
- 遮挡、重复、立即关闭和会话离开事件；
- 控件受阻时长、非预期跳转和整场计划变更；
- 硬规则违规；
- 所有指标的来源标签。

## 6. Demo 结构与构建顺序

### 6.1 三个主场景

| ID | 商业与体验冲突 | 核心产品能力 |
|---|---|---|
| S1 | 高保证量游戏广告遇到剧情高潮 | 延后至自然转场，同时保持可行履约 |
| S2 | 数码评测暂停查看参数，相关广告可投 | 使用低遮挡卡片，而不是用相关性掩盖打断 |
| S3 | 医疗结果/公益等高敏感任务遇到强广告 | 硬规则拒绝霸屏；商业压力不能覆盖安全规则 |

跨场景增加一个不单独占用主 Demo 的回归条件：同一品牌在片头和中插低遮挡位累计曝光后，后续方案触发跨形式频控。

### 6.2 实际工程顺序

1. **M0 工程证明：** 先只完成 S1，从场景数据到播放器、决策、事件和结果全链路跑通。
2. **M1 产品证明：** 加入轻量会话规划器、S2、S3 和跨形式频控，形成“整场计划 + 当前编排”的三场景 Demo。
3. **M2 操作台：** 将预置合同和素材从固定数据迁移到可编辑工作流。
4. **M3 实验：** 批量重放、指标计算、策略版本比较和导出。
5. **M4 可选 AI：** 上传许可素材，分析后经人工确认进入决策系统。

构建顺序不降低最终完成度，它只确保每个新增模块都接入已经工作的纵向闭环。

## 7. Baseline 定义

Baseline 是公开、可复现的比较策略，不代表腾讯视频真实算法：

1. 过滤已结束的活动和不兼容的素材形式；
2. 在剩余活动中选择优先级/商业值最高者；
3. 在名义机会时刻立即展示默认素材；
4. 只执行基础单素材频控；
5. 不理解情绪高潮、查看型暂停、遮挡区域或跨形式品牌疲劳。

其作用是展示 AdMind 新增了哪些决策，不是刻意制造一个愚蠢对手。Baseline 仍必须遵守基本合法性和广告标识要求；如果要演示危险旧体验，必须标为“问题重放”，不能把违规行为实现成默认产品能力。

## 8. AdMind 决策原则

### 8.1 两层商业决策

```text
Session Planner（会话规划器）
  输入：预计观看时长、安全窗口、合同压力、最大广告负荷、广告段长度、品牌间隔、观众集中/分散偏好
  输出：整场计划广告段、预留活动、未分配广告债务和风险
          ↓
Real-time Orchestrator（实时编排器）
  输入：当前场景、交互状态、实际曝光、反馈和会话计划
  输出：当前展示、延后、换已审批版本、撤下或无可行方案
```

Phase 1 的会话规划器是透明的确定性启发式，不假装解决全平台生产级库存分配；实时编排器仍是首先实现和完整测试的底层能力。计划不是死命令：暂停、拖动、离开页面、频控变化或敏感场景出现时必须重新验证，必要时产生版本化重规划。

### 8.2 用户任务与交互保护

在视频 MVP 内，系统区分：正常观看、查看画面、拖动进度、阅读弹幕/评论、准备返回或切换任务、页面后台和未知状态。地图导航等时间关键案例只作为跨领域证据，不进入第一版产品范围。

以下交互属于硬边界：

- 不得遮挡播放、进度、返回、关闭等必要控制；
- 不得自动打开广告页面或劫持返回操作；
- 广告跳转必须由明确的主动点击产生，关闭控件与跳转热区不得重叠；
- 用户开始拖动进度或准备离开时，非计费展示应撤下，已开始的强制素材按公开规则处理，不能伪装成误触；
- 从广告页面返回后必须恢复原内容、时间位置和可恢复的界面状态。

低强度的交互摩擦可以进入评分；误导跳转、必要控件遮挡和受保护任务冲突必须在评分前淘汰。

### 8.3 集中观看偏好

小样本中多数受访者倾向一次看完，但这不是市场比例，也不意味着所有素材都能拼成一个广告段。产品允许观众在场景支持时表达`CONSOLIDATED`或`DISTRIBUTED_SAFE_WINDOWS`偏好；规划器在以下硬约束内尽量满足：

- 每个广告段最大时长；
- 活动允许版位和时间窗；
- 竞争品牌分隔与频控；
- 素材完整性和已审批版本；
- 受保护上下文和必要控件；
- 合同可行性。

无法完全满足偏好时，系统展示原因和剩余广告计划，不能承诺“一次看完”后又静默追加广告。

### 8.4 当前机会的执行顺序

决策顺序固定为：

```text
1. 读取当前版本的会话计划和广告债务
2. 规范化输入、任务/交互状态和不确定性
3. 生成可选时间窗口与形式
4. 生成完整方案
5. 硬规则过滤
6. 对合格方案计算分项分数
7. 选择、延后、撤下或返回无可行方案
8. 写入原因、版本和回退
9. 记录交付与观众行为事件
10. 当现实状态偏离计划时触发版本化重规划
```

以下内容永远不是权重交易：

- 受保护/高敏感场景禁投；
- 未获得必要同意的个性化信号；
- 不在合同受众、时段或版位范围内；
- 未审批的素材或形式；
- 硬频控；
- 隐藏关闭、误导点击或强制误跳转。
- 遮挡必要控件、劫持返回操作或在主动拖动进度时强制覆盖。

## 9. 指标与“成功”的准确含义

### 9.1 Phase 1 主张

Phase 1 只验证：

> 在预置且公开的模拟条件下，AdMind 是否能保持合同可行性和零硬规则违规，同时选择规范化打断成本更低的方案。

它不验证真实用户留存、广告转化或平台收入提升。

### 9.2 必须展示的指标

| 指标 | 定义 | 来源标签 |
|---|---|---|
| 可行履约率 | 模拟周期内满足合同条件的交付数 / 需要交付数 | `simulated` |
| 规范化打断成本 | 由场景强度、对话连续性、字幕重要性、暂停意图、遮挡和形式成本组成的透明启发式分数 | `modelled` |
| 交互干扰成本 | 控件冲突、任务状态不兼容、返回/拖动阻碍等透明启发式分数；硬违规在评分前淘汰 | `modelled` |
| 硬规则违规数 | 被实际展示但违反硬规则的方案数量 | `observed-in-demo` |
| 跨形式品牌频次 | 同一会话中该品牌所有形式的可视曝光总数 | `observed-in-demo` |
| 内容恢复成功 | 广告后在预定完整边界恢复并继续播放 | `observed-in-demo` |
| 立即负反馈 | 广告出现后短窗口内的关闭、离开、误跳转、时机/重复/遮挡投诉 | `observed/user-test` |
| 计划履行/变更 | 实际广告段与当前会话计划一致的数量，以及带理由的重规划次数 | `observed-in-demo` |
| 控件受阻与非预期跳转 | 必要控件被广告阻断的时长和没有明确主动点击来源的跳转次数；合格目标均为 0 | `observed-in-demo` |

### 9.3 必须避免的表述

- “收入提升 20%”；
- “用户不再讨厌广告”；
- “AI 精准知道用户想买什么”；
- “腾讯的算法只看谁给钱多”；
- “经过 9 份访谈证明大多数用户……”；
- “注意力分数等于真实观看效果”。

## 10. 数据、隐私和证据边界

### 10.1 场景分析输入

只分析内容和播放事件：镜头/章节边界、字幕重要性、对话连续性、情绪强度、内容类别、敏感程度、遮挡区域、暂停持续时间和操作序列。

不使用摄像头、麦克风、面部或生理信号判断用户情绪。

### 10.2 定向证据等级

| 等级 | 含义 | Phase 1 用法 |
|---|---|---|
| T0 | 当前内容/场景上下文 | 默认且可在无身份模式使用 |
| T1 | 有来源和日期的媒体人群统计 | 仅作群体假设，不描述成个人事实 |
| T2 | 经同意的第一方会话意图 | 只在预置场景中模拟，显示来源和失效时间 |
| T3 | 搜索、商品页、购物车等商业意图 | 留作电商对照案例，不作为长视频默认能力 |

### 10.3 公开仓库规则

- 不提交含联系人、聊天头像、账号或病情细节的原始访谈和截图；
- 真实截图只用于私下设计参考，公开 UI 使用重新设计的虚构品牌；
- 所有模拟合同、价格、曝光和效果数据必须标记为 synthetic/simulated；
- 素材的许可或生成来源进入资产清单；
- 任何模型分析保存模型/提示版本、置信度和人工修正记录。

## 11. Phase 1 发布门槛

只有同时满足以下条件，才能进入“作品集可展示”状态：

- 三个主场景在无密钥模式下可运行；
- S1 的完整纵向闭环具备浏览器测试；
- 相同输入、配置和引擎版本得到相同决定；
- 每个淘汰候选都有机器可读理由码；
- 受保护场景无论怎样提高商业权重都不能展示禁用形式；
- 跨形式频控能阻止达到硬上限的品牌方案；
- 广告后内容恢复到预期边界；
- 页面明确区分模拟、建模、观察和用户测试指标；
- 页面能展示整场广告计划，集中/分散偏好只在合同和安全规则内生效；
- 拖动进度、返回页面、阅读弹幕/评论时，不发生必要控件遮挡和无意跳转；
- 不配置 AI 密钥时不影响主要演示；
- 公开仓库不含私人访谈、第三方未授权视频、真实广告价格或平台内部机制断言。

详细的可执行条件见 [Acceptance Tests v1](ACCEPTANCE_TESTS_V1.md)。

## 12. 仍然开放但不阻塞开工的问题

这些问题在开发过程中通过测试决定，不应让项目继续停留在调研阶段：

1. 播放器最终采用原生 Video API 还是成熟的 React 封装；
2. 场景时间轴的视觉形式；
3. S1 使用 6 秒全屏静音版本还是 6 秒分屏版本作为最佳方案；
4. 打断成本各特征的初始权重；
5. 会话规划器的默认最大总广告时长、单广告段上限和最小内容间隔；
6. 操作台在 Phase 2 使用独立应用还是同一应用中的角色路由；
7. 最终演示视频是实拍、许可素材还是 AI 生成的原创素材。

开放问题必须通过体验、工程或可解释性标准选择，不能根据“看起来更像 AI”选择。

## 13. 产品负责人确认项

开始搭仓库前，只需要确认以下五件事：

- [ ] 接受第一版只聚焦桌面端长视频模拟；
- [ ] 接受产品名和定位不改成泛 Agent；
- [ ] 接受三主场景和 S1 优先的构建顺序；
- [ ] 接受公开仓库只使用原创/许可内容和虚构商业数据；
- [ ] 接受第一版成功标准是“可行履约下减少建模打断”，不是宣称线上收益。

确认后，本文件与场景包、决策引擎规格、验收测试共同构成 Phase 1 的开发合同。
